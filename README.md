## 赛道二：离谱发明家

根据主办方指南，本赛道鼓励用 AI 制作有趣、出人意料的作品，方向包含但不限于 AI 整活工具、反常识交互。评审重点关注**脑洞的独特性、作品的趣味性和完整度，以及是否能让人会心一笑**。

下一步围绕一个具体场景确定创意、AI 的实际作用和可稳定演示的核心流程。具体作品尚未确定；本仓库记录赛道选择，不代表已完成主办方报名或作品提交。

## 当前产品构想

「人类观察报告：人类研究中心」准备把普通的人类日常行为包装成一份一本正经的研究报告。用户主动提交例如熬夜、拖延、反复打开冰箱等行为，AI 以外星研究员、官方调查员或哲学观察员等视角进行善意吐槽，并给出荒谬但无害的改进建议。

这是当前的创意方向，不代表已经完成实现。产品应吐槽行为和情境，不针对真实身份、受保护群体或他人隐私。

## 从这里开始

1. 与队友填写[需求说明](docs/需求说明.md)，确定一个用户、一种场景和一条能演示的核心流程。
2. 在下表认领工作，按[协作约定](CONTRIBUTING.md)使用功能分支和 Pull Request。
3. 选定技术栈后上传可运行的最小版本，在本 README 补充依赖、安装、配置、启动方式和示例输入。
4. 开发时逐步填写[AI 使用与素材记录](docs/AI使用与素材记录.md)，记录实际使用的工具及人工修改。
5. 临近提交时逐项检查[提交前清单](docs/提交前清单.md)。

## 运行与配置

当前没有可运行应用。确定技术栈并提交源码后，再填写经过验证的安装、启动、构建与部署步骤。

如需模型 API 或其他服务，届时增加只包含配置名称和占位值的 `.env.example`。真实密钥放在本地环境配置或部署平台中，含服务端密钥的接口由服务端调用。

## 公开内容与许可证

这个仓库是公开的。提交前检查暂存区，只上传与项目有关的代码、文档和可公开素材。完整聊天记录、未脱敏截图、账号密码及 API Key 不应提交；需要保留的原始过程资料可放在仓库外，或放入已忽略的 `private/` 目录。

团队尚未为自有作品选择开源许可证。使用第三方代码、素材、模型或数据集时，按其实际许可证保留必要的署名与声明，并在素材记录中注明来源。
