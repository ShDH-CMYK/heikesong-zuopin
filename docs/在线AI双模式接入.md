# 在线 AI 双模式接入说明

> 状态（2026-09-13）：该在线模式曾在一个分支上实现并验证，但**未合入当前提交构建**——当前 `game.js` 不含 `SUBTEXT_AI_ENABLED` 开关，页面始终使用本地词库。本文作为接入方案保留，供后续需要时按此实现；正文描述的开关与代理协议在合入代码前不会生效。

当前页面默认使用本地词库，适合比赛录屏和现场演示。页面不会自动请求在线服务，也不会在前端保存 API Key。

## 开启方式（方案，未合入当前构建）

部署一个服务端代理（推荐 Cloudflare Worker），然后在页面加载 `game.js` 之前设置：

```html
<script>
  window.SUBTEXT_AI_ENABLED = true;
  window.SUBTEXT_AI_ENDPOINT = '/api/chat';
</script>
```

代理接收：

```json
{
  "question": "用户的问题",
  "role": { "id": "doubao", "name": "暖球", "persona": "温柔安慰 · 克制吐槽" }
}
```

成功时返回：

```json
{
  "official": "礼貌的官方回复",
  "roast": "角色专属内心 OS"
}
```

前端会校验字段并限制长度。请求超过约 1.8 秒、返回非 2xx、JSON 格式不正确或代理未部署时，自动使用本地词库，不会在页面显示报错。比赛录屏建议保持默认本地模式；在线模式用于现场展示更自由的生成效果。

## 服务端要求

- API Key 只放在 Worker Secret 中，例如 `wrangler secret put AI_API_KEY`。
- 代理自行设置模型、系统提示词、15 秒以内的上游超时和一次限量重试。
- 只允许针对用户问题或行为吐槽，禁止针对身份和受保护群体。
- 不要把用户原文、API Key 或服务商响应写入公开日志。
- 上游模型和版本、使用日期、用途及人工修改记录，必须按真实情况更新 [AI使用与素材记录](AI使用与素材记录.md)。
