# 《潜台词 Subtext》创作说明

## 一、创作缘起

我们每天都在使用 AI，却只能看到它整理过的礼貌答案，看不到回答背后的犹豫、吐槽和角色差异。《潜台词 Subtext》把这层通常被隐藏的“后台真心话”变成可以亲自触发、观察和追问的互动体验。作品选择“离谱发明家”赛道，把一次普通提问改造成一场小型的人类观察实验：人类提出问题，AI 先认真回应，再忍不住说出心里话。

## 二、核心表达

作品的核心反差是“表面合规，内心诚实”。用户提出问题后，角色先显示一条完整的官方回复，约 0.6 秒后再出现专属的内心 OS。时间差让吐槽像是从后台泄露出来，也让五个角色的性格真正参与回答。吐槽只针对用户主动提交的问题或行为，不针对真实身份、群体或个人隐私。

## 三、互动设计

用户可以从五只研究员宠物中选择角色，点击预设话题或输入自己的问题。每次提问都会形成“用户问题—官方回复—内心 OS”的完整对话链。点击“戳它一下”或直接点击模型会触发角色反应；拖动、滚轮、双指操作和键盘控制可以查看模型的正面、侧面和背面。

作品把一次回复继续延展为可探索的叙事：切换角色时会出现“内部通讯 · 已截获”，连续三条离谱需求会点亮保密后台的红色告警；用户可以查看按顺序记录的日志并进行“当面质问”，首次质问后生成《潜台词结案报告》，汇总提问次数、离谱次数、告警状态和角色判词。这样，笑点不止停留在一句文案，而是形成可回看、可追问的闭环。

## 四、视觉与三维建模

五个角色使用统一的实验室界面和信息层级，但分别采用暖球、拆镜、班班、报错、小金五套性格设定。拆镜使用用户提供的 Blue 三维资产整理版；暖球、班班、报错和小金使用 Blender 脚本按已有立绘进行风格化体积重建，统一导出带 Idle/React 动画的 GLB。报错另有一版 FBX 转换模型在开发中评估过，因超出部署体积上限，最终未随构建发布。

网页使用一个 Three.js 场景按需加载角色，支持模型加载失败时回退到立绘，避免用户因设备或 WebGL 状态不同而无法完成体验。模型、贴图和 Three.js 运行依赖随站点提供，作品不依赖运行时 API Key。

## 五、AI 与人工协作

开发过程中使用 Codex（GPT，具体子版本未记录）协助创意梳理、代码编写、文案整理、Blender 脚本、模型审计和测试；使用 Blender 完成三维导入、材质整理、动作绑定或网页适配，使用 Python/Pillow 处理贴图，使用 Three.js 实现网页交互。人工负责确定赛道和创意方向、提供与筛选素材、改写角色文案、决定交互规则、检查五角色外观与动作，并对最终提交内容逐项验收。运行时回复来自本地词库和预设匹配，不调用在线大模型，也不上传用户输入。

## 六、创作边界与待确认事项

作品中的角色名为原创称呼，文件名中的历史资源名不代表第三方品牌授权。立绘、Blue.rar/FBX 资产、字体、图标和音效的原作者、生成工具、版本、使用日期及公开展示授权，需要由团队根据实际记录补齐并向主办方确认。本文只说明已经在仓库中能够核对的制作事实，不代替官方项目介绍模板，也不代表合规授权已经完成。
